# 场景文件格式（`*.twin.json`）

> 一句话：**布局真相必须能离开代码。**
>
> 只要场景只能由 `buildCenterScene()` 这类 TypeScript 函数算出来，改一根皮带就要
> 改代码、跑测试、重新构建，"一天内建一条线"就不成立。这份文档定义的 JSON 就是
> 那个可交换的中间物：CAD、MES 台账、手绘草图重建出来的布局，只要能落成这份
> 格式，就能直接进内核跑，不需要改一行 TS。

- 当前版本：`TWIN_SCENE_VERSION = 1`
- 规范实现：`packages/scene-schema/src/index.ts`（类型 + 校验 + 迁移）
- 读写实现：`packages/scene-schema/src/io.ts`（解析 / 序列化 / 摘要）
- 样例文件：`scenes/logistics-center-v1.twin.json`（45 实体，38.8 × 2.3 × 26.0 m）

---

## 1. 顶层结构

```jsonc
{
  "version": 1,            // 必填，必须是 1
  "id": "logistics-center",// 必填，非空字符串，场景内唯一即可
  "name": "智能物流中心",   // 必填，显示用（会顶在 Studio 标题栏）
  "metadata": { "floor": 1 },  // 可选，只允许 string/number/boolean
  "entities": [ /* 见下 */ ]
}
```

`validateTwinScene` 会一次性把所有问题报全（不是撞到第一个就停），
`parseSceneDocument` 更进一步：**永不抛异常**，坏输入一律转成 `issues` 列表。

## 2. 实体

```jsonc
{
  "id": "belt-io-a-station",       // 必填，场景内唯一
  "kind": "transport",             // 必填，设备类型（渲染与行为都靠它 + capabilities 认领）
  "transform": { "position": [4, 1.2, 5] },  // 必填，[x,y,z] 三个有限数字，单位米
  "capabilities": ["move"],        // 必填，字符串数组——**行为靠这个认领实体，不是靠 kind**
  "visual":  { "kind": "box", "color": "#8BD3C7", "size": [1.4, 0.6, 1.4] },
  "motion":  { "points": [[0,0.8,0],[8,0.8,0]], "speed": 1.2, "loop": "clamp" },
  "dataBindings": [{ "source": "mes", "key": "PLC.TAG.01", "signal": "progress" }],
  "attrs":  { "batch": "B-2201" },  // 只允许基元值
  "config": { "label": "入库站台 A" } // 任意结构，行为自己解释
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` / `kind` | ✅ | 非空字符串；`id` 场景内唯一 |
| `transform.position` | ✅ | `[x,y,z]`，米。Y 向上，XZ 为地平面 |
| `capabilities` | ✅ | 字符串数组。**这是行为认领实体的唯一依据** |
| `visual` | — | 渲染外观，内核完全不解释，只有渲染层读 |
| `motion` | — | 折线路径 + 速度；`loop`=`clamp`（停终点）/`repeat`（回起点） |
| `dataBindings` | — | 外部数据绑定，见 §4 |
| `attrs` / `config` | — | 过程属性 / 行为私有配置 |

> ⚠️ **`capabilities` 是分配的真正开关。** 导入外部布局最常见的失败是：
> 几何进来了，但没有行为认领这些实体，于是设备渲得出来却不参与仿真。
> Studio 的 `drivableKinds()` 会列出所有无人认领的 `kind`，场景面板直接提示。

## 3. 版本迁移

没有 `version` 字段的按 **v0** 处理，v0→v1 会自动：

- 补 `version: 1`
- `type` → `kind`（缺则 `unknown`）
- `{x,y,z}` 对象位置 → `[x,y,z]` 元组
- 补 `capabilities: []`
- 数字 `id` → 字符串

高于当前版本的文件**直接拒绝，不猜**。迁移说明会写进 `applied`，UI 展示给用户。

## 4. 外部数据绑定（`dataBindings`）

真实工厂几乎不可能每台设备都有数据，所以每个实体单独声明"外部能给我什么"：

| `signal` | 外部给什么 | 内核怎么换算 |
|---|---|---|
| `pose` | 位姿（`frame`: `world`/`local`） | 直接落位 |
| `progress` | 0…1 进度 | 乘路径长度 → 弧长（**要求同时声明 `motion`**） |
| `entry` | 进入时刻 | 用自身 `speed` × dt 推进（**要求 `motion`**） |
| `span` | 进入 / 离开时刻 | 区间内线性插值（**要求 `motion`**） |

`source` 语义上是"数据源 id"（CSV 列组 / MQTT 主题 / MES 接口），
`key` 是外部标识（PLC tag / CSV 主键 / MQTT key）。

> 目前唯一实现的 Adapter 是离线 CSV（`packages/data-source-csv`）。
> MQTT / WebSocket / OPC-UA 尚未实现，但**内核入口是统一的**
> （`world.ingestExternalFrame` → `resolveExternalMotion`），新增协议只需实现
> `ExternalFrameSource { feedTo, rewind }`，内核一行不用改。

## 5. 读写 API

```ts
import { parseSceneDocument, serializeSceneDocument, sceneSummary, sceneFileName } from '@twin-platform/scene-schema';

const result = parseSceneDocument(text);        // 永不抛异常
if (result.ok) {
  result.scene;    // 已迁移 + 校验过的场景
  result.applied;  // ['0→1: 补齐 version/capabilities…']
  result.summary;  // { entities, kinds, moving, bound, bounds }
} else {
  result.issues;   // [{ path: '$.entities[3].id', message: '实体 id 必须唯一。' }]
}

const text = serializeSceneDocument(scene);     // 缩进 2，version 顶到最前，便于 diff
```

**往返保证**：`serializeSceneDocument(s)` 的输出必然能被 `parseSceneDocument` 接受，
且 `roundTripIssues(s)` 为空。这条有回归测试钉住（同 seed 同帧数逐位一致），
一旦有人在场景里塞进函数 / 类实例 / `undefined`，导出就会自检失败而不是落地成废纸。

## 6. 从外部系统生成场景（对接指引）

| 来源 | 通常能给什么 | 映射到本格式 |
|---|---|---|
| **CAD / 图纸**（含 GRE 重建结果） | 设备轮廓、中心线、坐标 | 设备 → 实体 `transform.position`；路径中心线 → `motion.points`；尺寸 → `visual.size` |
| **MES / WMS 台账** | 设备编号、类型、产线归属 | 编号 → `id`；类型 → `kind` + `capabilities`；产线 → `metadata` |
| **PLC / SCADA 点位表** | tag 名、地址 | `dataBindings[].key` + `signal`（通常是 `progress` 或 `pose`） |
| **测绘 / 激光点云** | 真实米制坐标 | 直接是 `position`；注意统一 Y 向上、XZ 地平面 |

坐标约定：**米制，Y 向上，XZ 为地平面，右手系**。当前实现是单层，没有楼层概念——
多车间/多楼层需要靠 `metadata.floor` 自行约定（内核尚未解释）。

## 7. 已知限制

1. **没有服务端**：Studio 是纯静态站，导入靠浏览器 File API，刷新即丢。要持久化必须先有服务端。
2. **行为是静态装配的**：导入的场景若含插件不认识的 `kind`，几何能显示但不参与仿真（会有提示，不会静默）。
3. **单层、无经纬度**：不能表达厂区级多建筑布局。
4. **规模未验证**：当前样例 45 实体；1000+ 实体的渲染与step性能尚未压测。
