# 服务端持久化 · 云端部署

> 配套 `apps/server`（Bun 常驻进程）+ `storage-postgres`（PostgreSQL 后端）。
> 本文给**生产上云**的落地方案，不重复 `docs/服务端与持久化.md` 里已写的契约 / API / 鉴权细节。

## 0. 结论先行（推荐架构）

```
浏览器 ──► [边缘] ──► apps/server (Bun, 容器) ──► 托管 PostgreSQL
              │            │ 无状态，可多副本            │ RDS / TencentDB / PolarDB
              │            └ 共享一个托管 PG            │ 自动备份 / 主备
          Cloudflare Worker
          (注入 token，仅国内需自定义域名)
          或 国内域名 + Caddy + token（不走 Worker）
```

- **持久化后端只选 `postgres`**：托管 PostgreSQL 是云上唯一靠谱选择，`file` 后端（单 JSON）在容器里是临时存储、且大体积全量重写有瓶颈（见 `服务端与持久化.md` §8）。
- **服务端无状态**：连托管 PG 后，`apps/server` 本身不落盘、可水平扩多副本，前面挂 LB。
- **迁移自愈**：首次启动 `connectPostgresStorage` 自动跑 `migrations/*.sql`（幂等 + `_twin_migrations` 台账），不用手工 `psql`。

## 1. 上云前必改（阻断点）

`packages/storage-postgres/package.json` 里 `pg` 之前是 `devDependencies`，
而服务端是 `dynamic import('pg')` —— 一旦用 `--production` 构建或锁依赖，**运行时缺包**。
已改为 `dependencies`：

```jsonc
"dependencies": { "pg": "^8.13.0", /* ...workspace... */ },
"devDependencies": { "@electric-sql/pglite": "^0.5.8" /* 仅本地验证用 */ }
```

> 改完**必须在本机 `bun install` 刷新 `bun.lock`**（WSL 内 bun）再构建镜像，否则镜像内依赖滞后。
> 若云上想用 `pglite://`（免数据库单容器），再把 `@electric-sql/pglite` 也提进 `dependencies`。

## 2. PostgreSQL 云选型（国内优先）

| 厂商 | 产品 | 说明 |
|---|---|---|
| 阿里云 | **RDS PostgreSQL** / **PolarDB for PostgreSQL** | 国内最稳，控制台 + 自动备份 + 只读副本；PolarDB 弹性好 |
| 腾讯云 | **TencentDB for PostgreSQL** | 同档，内网延迟低 |
| 华为云 | **RDS for PostgreSQL** | 合规场景可选 |
| 海外 | Neon / Supabase / AWS RDS | 功能强但**国内访问慢**，仅面向海外用户时考虑 |

**要点**
- 开 **公网或内网地址**：容器在 ECS/ACK 内用**内网地址**最低延迟、最安全。
- 建库 `twin` + 专用账号（别用 `postgres` 超级户）。
- 开**自动备份** + 设置保留期；托管 PG 已自带，比自建稳。
- 连接串：`postgres://twin_user:密码@rm-xxx.rds.aliyuncs.com:5432/twin` → 填 `DATABASE_URL`。
- 表前缀用 `TWIN_PG_SCHEMA=twin`，与 public 隔离。

## 3. 服务端运行时部署

### 3.1 容器化（已提供 `apps/server/Dockerfile`）

基于 `oven/bun:1.3.12`（与 CI 同版本）。服务端由 Bun 直接跑 TS，**无 build 步骤**；
`bun install` 在镜像内重建 workspace 符号链接。构建：

```bash
docker build -f apps/server/Dockerfile -t twin-server:latest .
```

### 3.2 两种落地形态

**A. 轻量（单机够用）：ECS / 轻量应用服务器 + Docker Compose**
- `deploy/docker-compose.yml` 已就绪：`server` 服务连托管 PG，自托管 `postgres` 服务默认注释。
- 前面加 **Caddy/Nginx** 反代做 HTTPS + 域名；进程守护用 `restart: unless-stopped` 或 systemd。
- 适合当前阶段（单场景库、无多租户）。

**B. 规模化：ACK / TKE / CCE（Kubernetes）**
- 服务端 `Deployment`（多副本 + HPA）+ `Service`（ClusterIP）+ `Ingress`（域名/HTTPS）。
- `DATABASE_URL` / `TWIN_API_TOKEN` 走 `Secret`，不进镜像。
- 托管 PG 独立于集群（跨 AZ 主备）。
- 探针：用 `/api/health` + Bearer（见 §5）。

```yaml
# deploy/k8s.yaml 示例（节选）
apiVersion: apps/v1
kind: Deployment
metadata: { name: twin-server }
spec:
  replicas: 2
  selector: { matchLabels: { app: twin-server } }
  template:
    metadata: { labels: { app: twin-server } }
    spec:
      containers:
        - name: server
          image: twin-server:latest
          ports: [{ containerPort: 8787 }]
          env:
            - { name: TWIN_STORAGE, value: "postgres" }
            - name: PORT, value: "8787"
            - name: DATABASE_URL, valueFrom: { secretKeyRef: { name: twin-secrets, key: database-url } }
            - name: TWIN_API_TOKEN, valueFrom: { secretKeyRef: { name: twin-secrets, key: api-token } }
          readinessProbe:
            exec:
              command: ["bun", "-e", "fetch('http://127.0.0.1:8787/api/health',{headers:{'authorization':'Bearer '+(process.env.TWIN_API_TOKEN||'')}}).then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
            initialDelaySeconds: 10
            periodSeconds: 15
```

## 4. 接入边缘（两种选法）

### 4.1 沿用 Cloudflare Worker（现有 `apps/worker`）
- 把 `apps/server` 部署成**公网上游**（上面的 ECS/ACK），`wrangler secret put UPSTREAM` 指向它的公网 URL。
- `API_TOKEN` 与 `TWIN_API_TOKEN` 必须一致，否则上游全 401。
- **⚠️ 国内注意**：`workers.dev` 被 DNS 污染，必须绑**自定义域名**国内才能访问。

### 4.2 国内直连（不依赖 Cloudflare）
面向国内用户更省事：服务器挂**自有域名 + Caddy 自动 HTTPS**，token 仍由服务端校验
（`TWIN_API_TOKEN` 设上即可，`/api/*` 全 401 保护）。Studio 可由服务端同源托管
（`TWIN_STUDIO_DIST=apps/studio/dist`）或单独静态托管。

## 5. 探活 / 迁移 / 连接池

- **探活**：`/api/health` 受 token 保护（文档刻意不免检）。k8s/compose 探针必须带 `Bearer`，
  上面 Dockerfile / compose / k8s 示例都已带。`TWIN_API_TOKEN` 未设时服务端不鉴权，探针发空串也 200。
- **迁移**：首次启动自动跑，幂等；DB 账号需有建表/DDL 权限（或先人工在托管库跑一遍迁移）。
- **连接池**：`pg` 默认连接池有限；多副本 + 托管 PG 连接数上限小时，建议加 **PgBouncer**（事务模式）
  或调小每副本 `pg` pool size，避免连爆。
- **写入**：浏览器侧 `storage-http` 已批量（64 条 / 400ms），服务端 debounce 落盘；上云后瓶颈在 PG 写入吞吐，
  大音量场景看 `scripts/bench-scale.ts` 的落库吞吐做容量规划。

## 6. 备份 / 安全 / 合规

- **备份**：托管 PG 自动备份即可；`file` 后端才需要挂持久卷 + 卷快照（不推荐上云）。
- **密钥**：`DATABASE_URL` / `TWIN_API_TOKEN` 只进 Secret / `.env.local`，**绝不提交**。
- **传输**：公网一律 HTTPS（Worker 自定义域名 或 Caddy）；`DATABASE_URL` 优先用**内网地址**避免出公网。
- **多租户**：当前所有场景同一库、无按人隔离（见 `服务端与持久化.md` §8），企业多团队使用前需补。

## 7. 水平扩展（已具备条件）

服务端连托管 PG 后**完全无状态**，加副本只是加 `replica` + 前面 LB：
- 浏览器 `storage-http` 批量追加事件 → 任意副本处理，都写同一托管 PG。
- **续写 / 409 语义不变**：第二次录制走 `resumeFromStorage()` 把游标推到库内最新值，
  多副本下由 PG 单行锁 / `sequence` 单调保证，不会拼出假历史。
- 注意：录制器是单客户端单时间线，正常不会并发写同一场景；真要并发写同场景需在上层加锁。
