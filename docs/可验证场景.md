# 可验证场景公共层：trace / run / audit / replay / diff / report

> 对应《开源方向与行动计划》阶段 1。公共契约不依赖行业插件；Studio 不是运行前提。

## 包边界

| 包 | 责任 | 不做什么 |
| --- | --- | --- |
| `scene-spec` | `SceneTrace`、`AuditReport`、eval、插件锁、JSON 规范化与稳定哈希 | 不 import 内核，不认识物流或钓鱼 |
| `scene-runner` | 参考 `TwinWorld` 的 headless run、重算 replay、trace diff | 不渲染、不读挂钟、不插值 |
| `scene-audit` | 通用 invariant 执行器、eval harness、观察窗 / 沉默改动检查、HTML 报告 | 不自行推演世界 |

外部 runtime 只需生成 `scene-spec` 的 trace，就能复用 audit、diff 与 report；无需继承 `TwinWorld`。

## 最小运行

```ts
import { runTwinScene, replayTwinScene } from '@twin-platform/scene-runner';
import { renderAuditHtml } from '@twin-platform/scene-audit';
import { centerRuntimeInvariants, buildCenterScene, logisticsPlugin } from '@twin-platform/plugins-logistics';

const input = {
  scene: buildCenterScene(),
  seed: 7,
  step: 1 / 60,
  durationSeconds: 300,
  behaviors: logisticsPlugin.activate().behaviors,
  plugins: [{ id: 'logistics', version: '0.4.0' }],
  checks: centerRuntimeInvariants,
  metrics: (world) => ({ entities: world.listEntities().length }),
};

const first = runTwinScene(input);
const replayed = replayTwinScene(input, first.trace);
// replayed.diff.identical === true
const html = renderAuditHtml(first.report, first.trace, replayed.diff);
```

`steps` 与 `durationSeconds` 必须且只能提供一个；时长必须对应整数固定步。动作按 `atStep` 再按声明顺序执行，`atStep=n` 表示在第 n 步之前应用，允许在最后一步之后（`atStep=steps`）应用。

## Trace 证据

`SceneTrace` 固定包含：

- 场景 id 与 canonical scene hash；
- seed、固定步长、步数、有序插件锁；
- 可序列化动作记录；
- 完整事件流与 event hash；
- 最终 `WorldSnapshot`（对参考 runtime 而言）与 state hash。

对象键排序后生成 canonical JSON，数组顺序保持不变；`undefined` 对象字段按 JSON 语义省略，NaN / Infinity、类实例等直接拒绝。哈希使用 FNV-1a 32 位，用途是**回归比较**，不是安全签名。

内核内存日志有容量上限。runner 会检查应有事件数与实留事件数，容量不足直接抛错，绝不把缺头部的日志冒充完整 trace；长运行需提高 `eventLogSize`。

## 不变量与 eval

```ts
const conservation = {
  id: 'domain.conservation',
  description: '输入 = 输出 + 在制',
  check(world) {
    return true
      ? { notes: ['账实一致'] }
      : { violations: [{ where: 'goods', message: '物料不守恒' }] };
  },
};
```

`runAudit()` 按声明顺序同步执行检查。单条检查抛错会记录为 `ERROR`，后续检查仍执行；任何 `FAIL / ERROR` 都令报告不通过。领域 invariant 是纯检查，不修改世界。

`runEvalCases()` 将用户故事清单与可执行检查按 id 配对。缺检查函数、检查抛错都会形成失败结果，不会中断整份 eval。钓鱼的 `run-evals.ts` 与 `audit-scene.ts` 已共用这套执行器；物流闭环与物料守恒已抽成 `centerRuntimeInvariants`。

## 回放与差分

`replayTwinScene(input, baseline)` 会从场景与输入重新建世界并推进，不复用旧世界、不做状态插值。`diffTrace()` 比较完整 canonical trace，并返回：

- baseline / current trace hash；
- 是否逐字段一致；
- 第一处差异的 RFC 6901 JSON Pointer、差异类型与两侧值。

数组长度不同时，pointer 指向第一个缺失元素，而不是只指向父数组。比较顺序先运行输入、事件与末态，再比较派生哈希，避免 `/eventHash` 遮住真正的 `/events/N` 分歧。

## 观察窗与沉默改动

- `assessObservationWindow()`：窗口或样本不足时给出警告；它不会把“未观察到”解释成“没有差异”。
- `inspectSilentChange()`：动作或旋钮无变化且未显式声明 no-op 时标记 `suspicious`；`OBSERVE` 等合法不动必须显式声明。
- `renderAuditHtml()`：生成自包含 HTML，包含检查、指标、警告、首个分歧和完整 trace。报告不写挂钟时间，因此相同输入得到逐字节一致的 HTML。

## CLI 与 CI 门禁

`bun run scene <command>`（`packages/scene-cli`）是库能力之上的命令层，本身不推演世界：

| 命令 | 作用 | 退出码 |
| --- | --- | :---: |
| `run` | 跑一次并产出 trace / report / HTML / JUnit；默认不因不变量失败退出非 0，`--strict` 才挡 | 0（失败时 2 表示用法/执行错误） |
| `audit` | 同上，并按不变量与基线判定 | 失败 1 |
| `replay` | 重跑场景并与黄金基线 trace 比对；`--update` 生成/更新基线 | 分歧 1 |
| `diff` | 比较两个已有 trace 文件（`<current> <baseline>`） | 分歧 1 |
| `report` | 用已有 trace / report 渲染 HTML 报告 | 0 |
| `verify` | 验收外部 trace：JSON 结构、事件顺序，并由 TypeScript 端重算 `eventHash / stateHash` | 失败 1 |

常用输入：`--scene <file>` 或 `--template <plugin.template>`（`logistics.center` / `fishing.pond`）+ `--template-params`；`--seed / --step / --seconds / --steps / --actions`；`--out <dir>` 输出 `trace.json`、`report.json`、`report.html`、`junit.xml`。

JUnit 映射：一条不变量一个 `<testcase name="invariant:<id>">`；差分单独一个 `trace:diff`，失败信息带首个 JSON Pointer；套件属性带 `sceneHash / eventHash / stateHash / firstDivergence`。**不写 timestamp / time**，因此同输入产物逐字节一致。

黄金基线：`--baseline expected/trace.json` 指定基线，`--update` 写入。示例见 `examples/`（`hello/scene.json` + `hello/expected/trace.json` 是跨平台稳定的最小基线）；CI 示例见 `.github/workflows/ci.yml` 的“场景审计”步骤。

### 安装形态：单文件 CLI

`bun run scene:build` 把 CLI 打成 `packages/scene-cli/bin/scene.mjs`（单文件，shebang 为 `node`），
`npm pack` 出的 tarball 可直接 `npm i` 进任意目录，之后 `node bin/scene.mjs <command>` 即用——不需要仓库，也不需要 Bun。
发布入口是 `src/bin.ts`（无条件执行）；`src/cli.ts` 的入口守卫按文件名 `/cli\.ts$/` 判断，只服务 `bun run scene` 与测试 import，打包后不会命中。
依赖全部打进单文件，所以包清单里它们是 `devDependencies`：tarball 装出来没有运行时依赖。

### 故障注入演练

`examples/fault-injection/` 拿 `examples/community/mini-line/expected/trace.json` 改一处事件内容
（`/events/2/payload/status`：`idle` → `busy`），且**故意不重算** `eventHash`——这是伪造证据的典型形态。
`bun examples/fault-injection/check.ts` 用同一场景跑两遍：黄金基线必须一致（exit 0），篡改基线必须 exit 1，
且首个分歧精确到上面那个 pointer。产物的 HTML 与 JUnit 内嵌同一 pointer，可直接当演示材料。

## 外部 runtime：SimPy adapter

`adapters/simpy/` 是第一个非 `TwinWorld` runtime：Python + SimPy 执行随机到料、加工、检测的离散事件产线，直接生成公共 trace 与报告。CLI 不需要理解 SimPy 模型：

```bash
python3 adapters/simpy/run.py --spec adapters/simpy/scenes/two-stage-cell.json --out .scene-ci/simpy
bun run scene verify .scene-ci/simpy/trace.json --junit .scene-ci/simpy/verify-junit.xml
bun run scene diff .scene-ci/simpy/trace.json adapters/simpy/expected/trace.json
bun run scene report .scene-ci/simpy/trace.json .scene-ci/simpy/report.json --html .scene-ci/simpy/report.html
```

`verify` 由 TypeScript 端重算哈希，防止外部 runtime 自报自证；SimPy 原生检查覆盖工件链序、资源容量与物料守恒。依赖、场景格式与扩展边界见 [SimPy adapter 文档](../adapters/simpy/README.md)。

SimPy adapter 现在有两种运行方式：

- `simpy.factory.v1`：内置两段产线模型，不执行外部代码；
- `simpy.generic.v1`：**任意** SimPy 模型文件，经 AST 静态预检 + 受限沙箱执行，`simpy.Environment / Resource` 被换成带追踪的子类自动产出事件。

```bash
python3 adapters/simpy/run.py \
  --spec adapters/simpy/scenes/two-stage-generic.json --out .scene-ci/simpy-generic
bun run scene verify .scene-ci/simpy-generic/trace.json
bun run scene diff .scene-ci/simpy-generic/trace.json adapters/simpy/expected-generic/trace.json
```

### FMI 2.0 Co-Simulation adapter

`adapters/fmu/` 第二个外部 runtime：`ctypes` 真加载 FMU 二进制，解析 `modelDescription.xml`，按固定步长 `doStep` 推进。支持 FMI 2.0 Co-Simulation 的 real 变量、解包目录与 `.fmu`，不支持模型交换、事件模式与整型/布尔变量（会明确拒绝）。

```bash
python3 adapters/fmu/scripts/build_reference_fmu.py \
  --out-dir adapters/fmu/build/tank --fmu adapters/fmu/build/tank.fmu
python3 adapters/fmu/run.py --spec adapters/fmu/scenes/tank-step.json --out .scene-ci/fmu
bun run scene verify .scene-ci/fmu/trace.json
bun run scene diff .scene-ci/fmu/trace.json adapters/fmu/expected/trace.json
```

不变量：`fmu.input-applied`（输入调度逐条落地）、`fmu.output-range`（输出有限且不越限）、`fmu.time-grid`（末态对齐 stopTime、事件序号连续）。依赖、参考 FMU 与平台限制见 [FMI adapter 文档](../adapters/fmu/README.md)。

### OpenSCENARIO importer

`adapters/openscenario/` 导入外部场景格式：ASAM OpenSCENARIO 1.x XML 的**显式子集**（车辆、`LanePosition`、`SpeedAction`、时间触发）。不支持的构造会明确拒绝，不静默忽略。

```bash
python3 adapters/openscenario/run.py \
  --spec adapters/openscenario/scenes/follow-and-accelerate.json --out .scene-ci/osc
bun run scene verify .scene-ci/osc/trace.json
bun run scene diff .scene-ci/osc/trace.json adapters/openscenario/expected/trace.json
```

不变量：`openscenario.actions-applied`、`openscenario.road-bounds`、`openscenario.speed-limit`、`openscenario.gap`。子集边界与样例见 [OpenSCENARIO importer 文档](../adapters/openscenario/README.md)。

### 通用 introspector

`adapters/introspector/` 不跑仿真，只把外部工件看清楚并给出可运行草案：**不执行外部代码**（Python 走 AST、FMU 只读描述与压缩包条目、OpenSCENARIO 只解析 XML）。

```bash
python3 adapters/introspector/run.py \
  --target adapters/openscenario/scenes/follow-and-accelerate.xosc \
  --out .scene-ci/introspect/osc --emit-spec .scene-ci/introspect/osc-spec.json
```

产物 `introspection.json` 含模型族、变量 / 实体 / 资源、findings 与建议检查；`report.json` 的四条检查是：识别已知模型族、不支持构造显式列出、无挂钟 / 全局随机、抽取到可核对事实。草案不是文档——OpenSCENARIO 与 OpenDRIVE 草案都会被单测直接拿去跑。边界见 [通用 introspector 文档](../adapters/introspector/README.md)。

### OpenDRIVE 路网求解

`adapters/opendrive/` 解决 `LanePosition` 的解算：`planView`（`line` / `arc`）、车道宽度与 `laneOffset` 三次多项式、`road/link` 与 `junction/connection` 连通性、按道路长度加权的 Dijkstra 路由。`spiral`、`paramPoly3`、高程与超高被明确拒绝。

```bash
python3 adapters/opendrive/run.py \
  --spec adapters/opendrive/scenes/two-road-curve.json --out .scene-ci/odr
bun run scene verify .scene-ci/odr/trace.json
bun run scene diff .scene-ci/odr/trace.json adapters/opendrive/expected/trace.json
```

它同时接回 OpenSCENARIO importer：场景 JSON 给 `opendrive` 后，采样产出真实 `x / y / heading`，边界检查按车辆所在道路的长度与可用车道判定，车距按 `(roadId, laneId)` 分组。

**车道级跨道路自动换路**也已支持：`s` 越过当前道路末端时，按同道路 `lane link` → 路口 `laneLink` → 同侧最近车道求下一跳，并发出 `osc:road:enter`；走不通就保留越界，由边界检查抓住，不悄悄传送。新增不变量 `openscenario.lane-continuity`：换到的车道必须存在，且路网里确实有这条连接。样例 `adapters/openscenario/scenes/cross-on-opendrive.json`。不变量见 [OpenDRIVE 文档](../adapters/opendrive/README.md)。

### Scene package 目录约定

`bun run scene package <dir>` 校验一个 scene package：

```text
<package>/
  scene.json           必填：版本化场景
  plugins.lock.json    必填：[{ id, version, configHash? }]
  seed.json            必填：{ seed?, step?, seconds | steps, observation? }
  actions.json         可选：动作脚本
  invariants.json      可选：该验什么
  metrics.json         可选：指标口径
  expected/trace.json  可选：黄金基线
```

检查项：`package.layout`、`package.scene`、`package.plugin-lock`、`package.seed`、`package.baseline`。
基线的 `eventHash / stateHash` 由本端按 `scene-spec` 重算，改哈希不改事件会被抓住。示例包在 `examples/packages/hello/`。

### 插件 conformance kit

`packages/plugin-conformance` 提供开发者自检：

```ts
import { runConformance } from '@twin-platform/plugin-conformance';
const report = runConformance({ plugin, scene, steps: 240, sources });
```

检查项：`conformance.manifest`、`conformance.activate`（禁止异步激活）、`conformance.host-install`、`conformance.capabilities`（声明外贡献）、`conformance.determinism`（同种子两次指纹一致）、`conformance.source-hygiene`（`Math.random` / `Date.now` / `performance.now` / 定时器）。
不提供源码时只写 warning，不假装检查过。

## 当前边界

本阶段提供库能力、CLI、三个外部 adapter（SimPy、FMI 2.0 Co-Simulation、OpenSCENARIO 1.x 子集）与通用 introspector。
剩余项：复杂路口内部车道级路径与 `contactPoint=end` 的车道方向反转、任意 SimPy 模型的参数语义自动验证（目前只从默认值推断）、内置检查覆盖的场景类型还不够（现在只有环线、闭环中心与空场景三条）、贡献指南与外部贡献 adapter / 场景。物流与钓鱼仍是 reference plugins，3D Studio 仍是可选交互入口。
