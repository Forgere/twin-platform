## 1. 目标与边界

本项目是一个低成本、可扩展的数字孪生工作台。使用者应能通过版本化的场景数据、行业插件和外部数据接入，快速构建、运行、分析与回放一个场景。

一期验收目标：用物流插件和 CSV/MQTT 数据，在一天内建立一条可运行、可回放、可分析的产线场景。

不在一期范围：Kubernetes 实际落地（目前只有 `deploy/docker-compose.yml` 里的 k8s 片段）、远程第三方插件市场、Kafka、ClickHouse、复杂多租户计费。Docker **已进范围**：`apps/server/Dockerfile` + compose 已就绪（阶段 I）。

## 2. 已确定的技术决策

| 范围 | 决策 | 原因 |
| --- | --- | --- |
| 工作台 | SolidJS 2 + TypeScript + Vite | 细粒度响应式 UI，官方脚手架初始化 |
| 三维渲染 | 原生 Three.js | 不将世界内核绑定至任何 UI 框架；避免依赖尚未成熟的声明式 Three 封装 |
| 相机 | `camera-controls` | 统一轨道、平移、平滑转场、设备聚焦和预设机位 |
| 场景格式 | 版本化 JSON + JSON Schema | 可编辑、可校验、可迁移、可由工具生成 |
| 核心语言 | 纯 TypeScript | `world-kernel` 不依赖 DOM、Solid、Three 或数据库 |
| 主数据库 | PostgreSQL 18 | 同时覆盖关系数据、`jsonb` 场景配置、事件与指标；可采用时间分区 |
| 空间能力 | PostGIS（可选） | 仅在园区地图、空间区域和距离查询出现时启用 |
| 包管理器 | Bun | 使用 `bun add`、`bun install`、`bun run` 与 `bun.lock` |
| 本地开发 | 本机进程 + `.env.local` | 当前阶段不使用 Docker |
| 服务端 | Bun 常驻进程（`apps/server`） | 与内核同语言同锁文件，直接跑 TS 无 build 步骤 |
| 后端选择 | `file`（默认）/ `postgres`（生产） | 一个工厂 `createServerStorage` 切换，路由代码无感 |
| 边缘入口 | Cloudflare Worker 或服务端同源托管 | token 由 Worker secret 注入，**不进前端 bundle** |
| 本地 dev 拓扑 | vite `/api` 代理 → `:8787`，代理注入 token | dev 与部署同拓扑，去掉 CORS 与跨源分叉 |

SolidJS 2 目前仍处于 RC 阶段。版本升级必须在独立分支中执行，先通过类型检查、单元测试和 Studio 冒烟验证后再合并。

## 3. 架构

```text
apps/studio（Solid UI + Three 视口 + 世界内核，全在浏览器进程里）
  ├─ 命令：选择实体 / 聚焦 / 切换图层 / 控制时间轴
  ├─ 订阅：FrameDelta（只消费帧差量，不自己推演状态）
  ├─ 三维：src/scene/TwinSceneController.ts（renderer-three 尚未抽出 → §9-4）
  └─ packages/world-kernel（实体 / 行为 / 固定步长 / 快照 / 回放，零 UI 依赖）
                  │
                  │  同源 /api：dev 走 vite 代理注入 token；线上走 Worker 注入 token
                  ▼
packages/storage-http（浏览器侧仓储，事件攒批 64 条 / 400ms）
                  ▼
apps/worker（可选边缘：静态资产 + /api 反代 + 注入 Authorization）
                  ▼
apps/server（Bun：/api/* 鉴权 → createServerStorage 单点选后端）
  ├─ storage-file      默认 data/twin.json（零依赖）
  ├─ storage-postgres  TWIN_STORAGE=postgres / DATABASE_URL，启动自动迁移
  └─ storage-memory    仅测试
                  ▼
PostgreSQL / 可选 PostGIS
```

接口的唯一来源是 `packages/storage-contracts`（`TwinStorage`）：`storage-*` 各自实现同一套接口，并跑同一份 `storage-testkit` 契约测试；服务端只在 `createServerStorage` 这一个工厂里选后端，路由代码对后端无感。

`world-kernel` 是深 Module：调用方只通过少量 Interface 操作世界，例如 `loadScene`、`dispatch`、`advance`、`seek`、`snapshot`。Three 渲染、Solid 状态、SQL 和数据源协议均属于其外部 Adapter。

## 5. 核心模型

```ts
type TwinEntity = {
  id: string
  kind: string
  transform: Transform
  capabilities: string[]
  visual?: VisualBinding
  dataBindings?: DataBinding[]
  config?: Record<string, unknown>
}
```

插件分为 `renderer`、`data-source`、`behavior`、`analytics`、`panel`、`asset` 六类。插件通过 manifest 声明可提供的能力、配置 Schema 和兼容的 SDK 版本；一期仅加载随项目构建的本地插件，不执行任意远程 JavaScript。

## 6. PostgreSQL 数据模型

| 表 | 用途 |
| --- | --- |
| `projects` | 项目与访问归属 |
| `scene_versions` | 场景文档修订历史（整文档快照 + `scene_ops` 增量，共用单调修订号，任意版本可重建） |
| `plugin_installations` | 启用插件、锁定版本、配置 |
| `replay_sessions` | 回放/仿真的场景与插件锁定信息、seed、模式 |
| `world_snapshots` | 指定 sequence 的完整或增量世界快照 |
| `twin_events` | 不可变输入、状态、告警和用户操作事件 |
| `entity_state_latest` | 面向实时工作台的最新状态投影 |
| `metric_rollups` | 分钟、小时、天聚合指标 |
| `assets` | GLB、图片、点云、视频等资产元数据与外部地址 |

`twin_events` 必须带有 `session_id`、严格单调的 `sequence`、`occurred_at` 与 `received_at`。按时间分区并索引 `(project_id, entity_id, occurred_at)`；扩展属性保存为 `jsonb`。

## 7. 回放与加速

支持两种模式：

1. **状态回放**：从最近快照开始按 sequence 重放真实事件；支持 0.25× 到 100×。
2. **确定性仿真回放**：用场景版本、插件锁、固定步长、seed 与输入命令重新推进；可无渲染高速计算，并从历史时刻分叉推演。

时间轴 Interface 至少提供 `play(speed)`、`pause()`、`seek(time)` 和 `step(dt)`。高倍速下渲染 Adapter 可跳过中间帧，但不能跳过世界内核事件。

### 8.4 阶段 J：实时编辑场景（ops 化）✅

**起点**：Studio 是**只读**查看器——只有拾取 / 高亮 / 聚焦，属性面板是只读 `<dl>`，全仓没有一个改数值的输入框；改布局的唯一方式是整文档导入导出 + 显式"保存到服务端"按钮（`ScenePanel.tsx:211`）。

- [x] 选中实体后可编辑 `position` / `rotation`：属性面板输入框（`components/PoseEditor.tsx`：位置三轴 + 朝向 Y）+ 画布内拖拽（`TwinSceneController`：按下即待命、越过 6cm 阈值才算拖，射线投到过实体高度的水平面，Esc / 取消回滚预览）。
- [x] **编辑写声明、不写运行时**：`TwinWorld.applySceneOps()` 只换 `scene.entities` 数组（结构共享，场景对象引用不变），再**单向**把运行时位姿同步过去；运行时位姿永不回写声明。同步的还有 `baseTransform`（"以声明为原点"的外部坐标系）与 `state.declaration` 引用。
- [x] 编辑产物是**结构化 ops**：`packages/scene-schema/src/ops.ts` 的 `SceneOp`（`{ type:'setTransform', entityId, before, after }`），纯函数 `applySceneOps` 结构共享、`before` 对不上即拒（阶段 K 直接升级成乐观锁）、结果必须仍然过 `validateTwinScene`。**手动编辑与将来的 AI 编辑共用这套 ops**——两者只是不同的生产者。
- [x] "仿真播放中能否编辑"的语义（已定，**不自动暂停**）：**播放中可编辑**，改声明 + 同步运行时，下一帧生效；被接管的实体直接禁用并给出内核给的原因（四类：运行时生成无声明 / 声明了 `motion` / 位姿由外部数据源驱动 / 行为正在改写位姿）。判定集中在 `world.poseEditability()`，UI 只展示不猜。
- [x] ops 先只落前端（`StudioSession.layoutOps()`），存储侧留接口；同时连着服务端时**去抖 900ms 自动保存整文档**（走已有 `putScene`，新存储通道留给阶段 K）。

**顺手修掉的三个隐患**（不修编辑就不可用）：

1. `runSteps(0)` 原来直接给空帧 → **暂停时编辑画面不动**；改为照样刷 dirty（`world.ts:178-184`）。
2. `ReplayController.advance` 非播放态直取世界空帧 → 绕过 `onFrame`，录制器收不到编辑帧；改走 `runSteps(0)`。
3. 渲染层更新位姿时 `rotation.y` **绝对赋值**，会把模型工厂自己转过的角度抹掉（皮带一改位置就转正）；改为 `工厂角度 + 当前朝向`，创建时记下 `baseRotationY`。

### 8.5 阶段 K：场景版本化与回滚 ✅

**结论**：场景有两条写入通道——`putScene`（整文档快照：导入 / 发布 / 回滚点）与
`appendOps`（细粒度布局变更，带 `baseVersion` 乐观锁）。两者共用**同一条跨表单调修订号**
（v1 首次写入，之后每次 `putScene` / `appendOps` +1），因此任意 vN 都能精确重建。

- [x] 仓储契约加 ops 通道：`appendOps(sceneId, baseVersion, ops)` + `listVersions` / `getVersion`；

## 9. 已知问题（发现即登记，修掉就移到对应阶段并从这里删除）

1. **`bun run test` 不含 Studio**：根 `test` 只跑 `packages apps/server apps/worker`，组件测试要另跑 `cd apps/studio && bun x vitest run`。
2. **服务端能力无 UI**：`/api/sessions`、`/api/snapshots/query`、`/api/metrics` 端点都在，Studio 一个都没读（`apps/studio/src` 内 grep `sessions.` / `snapshots.query` 零命中）→ 阶段 L。
3. **数据源未进产品**：`data-source-mqtt` 只被 `scripts/live-twin.ts` 用，`data-source-opcua` 全仓零运行时 import → 阶段 M。
4. **`renderer-three` 未抽出**：三维控制器仍在 `apps/studio/src/scene/TwinSceneController.ts`（阶段 C 起的遗留，不阻塞任何事）。
5. **workspaces 配置漂移**：根 `package.json` 的 `workspaces` 含 `plugins/*` 但该目录不存在（领域插件已落在 `packages/plugins-logistics`）——建议删掉这个 glob。
6. **布局数据化仍是 P0**：阶段 J 的 ops 与阶段 K 的版本化已就位，仍缺布局 DSL 与 AI 生产者（原 `docs/架构复盘-2026-09-15.md` 已随文档清理删除，其 L115 结论并入本条）。
7. **seek 与布局版本的语义分叉**（阶段 J 引入，K 未消除）：布局属于**场景文档**、不进 `WorldSnapshot`（受内核确定性规则约束，见 §2）。往回 seek 时位姿按**当时快照**显示，与当前声明可能不一致；要看历史布局需显式查看 / 回滚到某个文档版本，seek 本身不会切换文档。
8. **朝向只认 Y**（阶段 J 引入）：渲染层对模型朝向只应用 `rotation[1]`（X/Z 是给模型工厂造型用的）；要支持任意轴朝向得先改渲染层的位姿应用逻辑。
9. **浏览器工具断连**：`browser.disconnected`，阶段 K 的版本列表 / diff / 回滚**没有做过页面级冒烟**（组件测试与接口冒烟已覆盖契约，但 WebGL 交互链路没验）——桌面端连上浏览器后人工过一遍。

## 10. 质量门槛

- 每个跨包 Module 只暴露稳定、可测试的 Interface，禁止跨包访问内部实现。
- 场景、插件配置与事件 payload 必须可序列化且有 Schema 校验。
- 仿真不得使用未注入的 `Math.random()` 或浏览器时间。
- 每次场景、插件或内核行为变更都必须包含版本和迁移策略。
- `renderer-three` 不保存业务真相；它只消费世界状态与发送命令。
- 每一阶段完成前运行 `bun run typecheck`、`bun run test` 与相应 Studio 冒烟验证。
- 内核代码的确定性回归必须有测试：同种子两次运行比对指纹，而不是"看起来对"。
- 新增包必须在根 `tsconfig.json` 的 `paths` 与根 `typecheck:packages` 脚本里登记，否则 Windows 侧 IDE 与 CI 都解析不到。
- 阶段完成后：细节移入 [已完成阶段归档](./已完成阶段归档.md)，主文档 §8.1 只更新一行状态。
