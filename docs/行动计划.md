# Twin Platform 行动计划

## 1. 目标与边界

本项目是一个低成本、可扩展的数字孪生工作台。使用者应能通过版本化的场景数据、行业插件和外部数据接入，快速构建、运行、分析与回放一个场景。

一期验收目标：用物流插件和 CSV/MQTT 数据，在一天内建立一条可运行、可回放、可分析的产线场景。

不在一期范围：Docker、Kubernetes、远程第三方插件市场、Kafka、ClickHouse、复杂多租户计费。

## 2. 已确定的技术决策

| 范围 | 决策 | 原因 |
| --- | --- | --- |
| 工作台 | SolidJS 2 + TypeScript + Vite | 细粒度响应式 UI，官方脚手架初始化 |
| 三维渲染 | 原生 Three.js | 不将世界内核绑定至任何 UI 框架；避免依赖尚未成熟的声明式 Three 封装 |
| 相机 | `camera-controls` | 统一轨道、平移、平滑转场、设备聚焦和预设机位 |
| 场景格式 | 版本化 JSON + JSON Schema | 可编辑、可校验、可迁移、可由工具生成 |
| 核心语言 | 纯 TypeScript | `world-kernel` 不依赖 DOM、Solid、Three 或数据库 |
| 主数据库 | PostgreSQL 18 | 同时覆盖关系数据、`jsonb` 场景配置、事件与指标；可采用时间分区 |
| 空间能力 | PostGIS（可选） | 仅在园区地图、空间区域和距离查询出现时启用 |
| 包管理器 | Bun | 使用 `bun add`、`bun install`、`bun run` 与 `bun.lock` |
| 本地开发 | 本机进程 + `.env.local` | 当前阶段不使用 Docker |

SolidJS 2 目前仍处于 RC 阶段。版本升级必须在独立分支中执行，先通过类型检查、单元测试和 Studio 冒烟验证后再合并。

## 3. 架构

```text
apps/studio (Solid UI)
  ├─ 命令：选择实体 / 聚焦 / 切换图层 / 控制时间轴
  └─ 订阅：拾取结果 / 世界状态 / 时间轴状态 / 性能信息
                  │
                  ▼
packages/renderer-three
  ├─ Three 场景、资源、拾取和渲染循环
  └─ CameraController（camera-controls）
                  │
                  ▼
packages/world-kernel
  ├─ 实体、能力、状态、事件、时间轴、仿真
  └─ Repository Interface
         ├─ storage-memory（浏览器演示与测试）
         └─ storage-postgres（服务端持久化）
                  │
                  ▼
PostgreSQL / 可选 PostGIS
```

`world-kernel` 是深 Module：调用方只通过少量 Interface 操作世界，例如 `loadScene`、`dispatch`、`advance`、`seek`、`snapshot`。Three 渲染、Solid 状态、SQL 和数据源协议均属于其外部 Adapter。

## 4. 仓库规划

```text
twin-platform/
  apps/
    studio/                  # 当前 Solid 工作台（重构进入此目录）
  packages/
    scene-schema/            # TwinScene Schema、版本迁移、校验
    world-kernel/            # 世界状态、事件、仿真、时间轴
    plugin-sdk/              # 插件 manifest、能力与生命周期
    renderer-three/          # 原生 Three Renderer Adapter
    storage-contracts/       # Repository Interface
    storage-memory/          # 内存 Adapter
    storage-postgres/        # PostgreSQL Adapter 与迁移
    storage-testkit/         # 供各 Adapter 共用的仓储契约测试
    replay-core/             # 会话录制与确定性时间轴回放
    data-source-csv/         # CSV 外部数据源 Adapter
    analytics-core/          # 窗口聚合、规则、指标
  plugins/
    logistics/               # 从 r3f-tools 迁移的输送线领域能力
  docs/
```

当前由官方脚手架生成的应用先保留在仓库根目录；建立 workspace 后迁移到 `apps/studio`，不在没有测试保护的情况下直接移动。

## 5. 核心模型

```ts
type TwinEntity = {
  id: string
  kind: string
  transform: Transform
  capabilities: string[]
  visual?: VisualBinding
  dataBindings?: DataBinding[]
  config?: Record<string, unknown>
}
```

插件分为 `renderer`、`data-source`、`behavior`、`analytics`、`panel`、`asset` 六类。插件通过 manifest 声明可提供的能力、配置 Schema 和兼容的 SDK 版本；一期仅加载随项目构建的本地插件，不执行任意远程 JavaScript。

## 6. PostgreSQL 数据模型

| 表 | 用途 |
| --- | --- |
| `projects` | 项目与访问归属 |
| `scene_versions` | 场景 JSON、Schema 版本、发布状态 |
| `plugin_installations` | 启用插件、锁定版本、配置 |
| `replay_sessions` | 回放/仿真的场景与插件锁定信息、seed、模式 |
| `world_snapshots` | 指定 sequence 的完整或增量世界快照 |
| `twin_events` | 不可变输入、状态、告警和用户操作事件 |
| `entity_state_latest` | 面向实时工作台的最新状态投影 |
| `metric_rollups` | 分钟、小时、天聚合指标 |
| `assets` | GLB、图片、点云、视频等资产元数据与外部地址 |

`twin_events` 必须带有 `session_id`、严格单调的 `sequence`、`occurred_at` 与 `received_at`。按时间分区并索引 `(project_id, entity_id, occurred_at)`；扩展属性保存为 `jsonb`。

## 7. 回放与加速

支持两种模式：

1. **状态回放**：从最近快照开始按 sequence 重放真实事件；支持 0.25× 到 100×。
2. **确定性仿真回放**：用场景版本、插件锁、固定步长、seed 与输入命令重新推进；可无渲染高速计算，并从历史时刻分叉推演。

时间轴 Interface 至少提供 `play(speed)`、`pause()`、`seek(time)` 和 `step(dt)`。高倍速下渲染 Adapter 可跳过中间帧，但不能跳过世界内核事件。

| r3f-tools 的启发 | twin-platform 的落地 |

#### 阶段 C 落地说明

| 能力 | 落地位置 |
| --- | --- |
| 时间轴控制器 | `packages/replay-core/src/controller.ts`：`play/pause/setSpeed/advance/stepFrames/seek/snapshot`；倍速只改变"一帧吃几个步长"，步长本身不变，所以 1× 与 50× 跑完同一段时间的世界指纹一致 |
| 定位靠重算 | `seek(t)` = 取不晚于 t 的最近快照 → `world.restoreFrom` → `events.truncateAfter` → 按固定步长推到 t；没有快照就从头重算 |
| 往回跳即分叉 | `EventRepository.truncateAfter(sceneId, sequence)`：回跳后旧时间线之后的事件必须截断，否则回放出来的是两条时间线拼成的假历史 |
| 会话录制 | `packages/replay-core/src/recorder.ts`：事件落库 + 周期快照 + 最新状态投影 + 指标聚合；只搬运不推演，开着录制与关着录制的世界指纹必须一致 |
| 回放一致性指纹 | `packages/replay-core/src/fingerprint.ts`：同种子两次运行逐位比对，而不是"看起来对" |
| CSV 数据源 | `packages/data-source-csv`：`pose / progress / entry / span` 四类信号解析 + 可重放帧源（`rewind()` 后重喂得到同一帧序列） |
| PostgreSQL | `packages/storage-postgres`：`migrations/001_init.sql`（`twin_events` 按 `received_at` 时间分区 + 默认分区兜底、`world_snapshots`、`entity_state_latest`、`metric_rollups`、`replay_sessions`），全部 SQL 走参数绑定 |
| 契约测试 | `packages/storage-testkit`：`storage-memory` 与 `storage-postgres` 跑同一套断言；新增 Adapter 只要实现接口并调用它即可证明行为一致 |
| Studio 时间轴 UI | `apps/studio/src/components/TimelineBar.tsx`（播放/暂停/倍速/单步/拖拽定位）、`EventLogPanel.tsx`、`DataSourcePanel.tsx`；会话装配在 `apps/studio/src/scene/studioSession.ts` |

新增包：`replay-core`、`data-source-csv`、`storage-postgres`、`storage-testkit`。

内核侧补充：`world.runSteps(count)`（一次刷多个步、只在最后产一次帧差量）、`maxStepsPerAdvance` 选项、`EventLog.drainEvents()`。

测试：`bun test packages` 104 个用例全绿，覆盖 10× 回放一致性、快照恢复后重算、分叉截断、CSV 解析与重放、pg SQL 生成与迁移脚本。

## 9. 质量门槛

- 每个跨包 Module 只暴露稳定、可测试的 Interface，禁止跨包访问内部实现。
- 场景、插件配置与事件 payload 必须可序列化且有 Schema 校验。
- 仿真不得使用未注入的 `Math.random()` 或浏览器时间。
- 每次场景、插件或内核行为变更都必须包含版本和迁移策略。
- `renderer-three` 不保存业务真相；它只消费世界状态与发送命令。
- 每一阶段完成前运行 `bun run typecheck`、`bun run test` 与相应 Studio 冒烟验证。
- 内核代码的确定性回归必须有测试：同种子两次运行比对指纹，而不是"看起来对"。
- 新增包必须在根 `tsconfig.json` 的 `paths` 与根 `typecheck:packages` 脚本里登记，否则 Windows 侧 IDE 与 CI 都解析不到。
